Optimal Binary Search Tree

“An Optimal Binary Search Tree is a Binary Search Tree arranged to minimize the total weighted search cost based on the frequency of searching each key.”

Optimal Binary Search Tree Concept

Core Concepts

Fundamentals of Optimal BST

Key principles governing binary search tree structures and weighted search costs.

Binary Search Tree

A Binary Search Tree is a tree in which smaller keys are placed on the left side and larger keys are placed on the right side.

Optimal Binary Search Tree

An Optimal Binary Search Tree is a BST arranged in such a way that the expected or weighted search cost is minimized.

Search Frequency

Search frequency indicates how often a particular key is searched. A frequently searched key should generally be placed closer to the root.

Procedure

Dynamic Programming Algorithm

The step-by-step bottom-up process to construct an Optimal Binary Search Tree.

1
Take sorted keys and their search frequencies.
2
Calculate the sum of frequencies for each range.
3
Create the Dynamic Programming cost table.
4
Consider subtrees of different lengths.
5
Try every possible key as the root.
6
Calculate the cost for each possible root.
7
Select the root with minimum cost.
8
Store the selected root.
9
Repeat for all subproblems.
10
Construct the final Optimal Binary Search Tree.
Mathematical Formulation

Mathematical Formula

The dynamic programming recurrence and search cost computation.

Recurrence Relation

Cost(i,j) = min { Cost(i,r−1) + Cost(r+1,j) } + Sum(i,j)

(where candidate root \(r\) is evaluated from \(i\) to \(j\))

i First key in range
j Last key in range
r Possible root (\(i \le r \le j\))
Sum(i,j) Sum of frequencies between \(i\) and \(j\)

Weighted Search Cost Equation

The search cost of any key in the tree is calculated by multiplying its frequency by its level, where the root level = 1.

Search Cost = Frequency × Level

Performance

Complexity Analysis

Asymptotic time and space efficiency of the Dynamic Programming approach.

Time Complexity
O(n³)

The algorithm utilizes three nested loops:

  • Subtree length \(L = 2\) to \(n\)
  • Starting index \(i = 1\) to \(n - L + 1\)
  • Root candidate \(r = i\) to \(j\)
Space Complexity
O(n²)

The algorithm stores subproblem solutions in 2D arrays:

  • Cost table \(C[n+1][n+1]\)
  • Root table \(R[n+1][n+1]\)
  • Frequency sum table \(W[n+1][n+1]\)
Approach Time Complexity Space Complexity Optimality
Brute Force Exponential: O(4ⁿ / n³/²) O(n) Guaranteed (Intractable for large n)
Dynamic Programming Polynomial: O(n³) O(n²) Guaranteed (Globally Optimal)
